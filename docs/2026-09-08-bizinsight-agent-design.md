# BizInsight 企业经营异常诊断智能体设计规格

- 日期：2026-09-08
- 状态：设计已确认
- 目标周期：10 个工作日完成 MVP，另用 2～3 天整理复盘、演示与面试材料
- 开发方式：以 AgentScope 官方 `agentscope-samples/alias` 为参考与选择性迁移底座，基于 AgentScope 2.0.7 独立实现

## 1. 项目背景

本项目面向以软件平台、订阅服务和数字化解决方案为主营业务的 ToB 科技企业。此类企业的销售、合同、订阅、产品使用、项目交付、客服和回款数据通常分散在不同系统中。管理者发现收入、毛利或续费异常后，需要跨部门收集并拼接信息，分析周期长且容易依赖单一指标。

项目使用完全虚构的“云衡数科有限公司”及合成数据，不使用浩云科技股份有限公司的内部数据，也不宣称项目已在浩云科技生产环境部署。项目可在简历中表述为结合 ToB 数字化产品测试经历独立设计和实现的工程项目。

## 2. 产品定义

产品名称为 **BizInsight Agent——面向 ToB 科技企业的经营异常诊断与决策协同智能体**。

用户通过自然语言提出经营问题。系统自动规范问题、拆解分析任务、调度专业 Agent、查询多源数据、检索企业文档与外部信息、审查证据，最终生成带指标、图表、来源、置信度和行动建议的经营分析报告。

主要用户是企业经营分析负责人或业务管理者。

黄金验证问题为：

> 分析公司 2026 年第二季度经营表现下降的主要原因。请结合销售商机、合同、项目交付、客户续费、产品使用和客服工单进行分析，并参考外部行业信息，给出下季度改进建议。

黄金问题用于验证完整能力，不会被硬编码成系统唯一能回答的问题。评测集还覆盖销售、续费、产品、交付、客服、数据缺失和证据冲突等问题。

## 3. 设计目标

1. 完成从经营问题到可追溯报告的端到端闭环。
2. 关键数字由确定性 SQL/Python 工具计算，而非由大模型心算。
3. 所有关键结论带证据，证据不足时明确说明限制。
4. 通过 Leader–Worker 协作展示 AgentScope 多智能体能力。
5. 通过统一数据接口支持未来替换为真实数据库或企业 API。
6. 在线搜索失败时仍能完成内部经营分析。
7. 提供可重复的数据生成程序、自动评测和演示脚本。

## 4. 非目标

MVP 不连接浩云科技内部系统，不使用真实企业数据，不自动修改 CRM 或财务系统，不自动发送邮件，不构建复杂预测模型，不开发全新前端，不保留 Alias 的全部运行模式，不实现 Alias 的完整长期记忆、用户、数据库和 Alembic 后端，也不实现生产级多租户权限体系。

### 5.2 展示的 AgentScope 能力

- Agent Team / Leader–Worker 多智能体协作与任务规划。
- Agent/ReAct 循环和专业 Toolkit 权限隔离。
- 顺序与并行任务执行。
- Pydantic 结构化计划、Finding 和 Review 输出。
- RAG 检索企业内部文档。
- 自定义工具、外部搜索工具和只读数据库工具。
- 权限检查、工具白名单和受控文件输出。

- Agent Service 的会话与服务入口。
- 可选工作空间或 Docker 沙箱增强。

项目不以主观口号证明框架“绝对优越”，而是通过跨数据源、多角色协作、证据审查和自动评测，具体展示相对普通单 Agent 聊天机器人的工程优势。

## 6. 总体架构

系统包含六个 Agent：

1. `BizInsightLeader`
2. `FinanceSalesAgent`
3. `CustomerProductAgent`
4. `DeliveryAgent`
5. `ExternalResearchAgent`
6. `EvidenceReviewerAgent`

客服数据归 `CustomerProductAgent` 分析，因为产品使用、工单与续费需要联合分析。报告生成不是独立 Agent：Leader 负责综合已通过审查的结论，确定性的 `ReportBuilder` 工具负责渲染 Markdown、HTML 和图表。

```text
AgentScope Web UI / CLI
          |
          v
BizInsightLeader
  |       |       |       |
  v       v       v       v
财务销售  客户产品  项目交付  外部情报
  \       |       |       /
          v
EvidenceReviewer
          |
   一次定向返工（必要时）
          |
          v
Leader 综合 + ReportBuilder
          |
          v
Markdown / HTML / 图表 / 证据索引
```

## 7. Agent 职责

### 7.1 BizInsightLeader

- 规范用户目标、时间范围、对比口径和业务对象。
- 生成最多四个并行分析子任务。
- 为每个任务选择 Worker、数据集和交付要求。
- 汇总 Finding，向 Reviewer 发起审查。
- 根据审查结果触发最多一次定向返工。
- 只基于通过审查或明确标记限制的 Finding 生成最终综合结论。

### 7.2 FinanceSalesAgent

- 计算收入、成本、毛利、回款、商机数量和赢单率。
- 对比季度、地区、行业、产品线和客户规模。
- 分析商机阶段、输单原因、合同和回款异常。

### 7.3 CustomerProductAgent

- 计算续费率、流失率、升级和降级比例。
- 分析活跃用户、登录、工作流和核心功能使用。
- 分析工单类别、严重程度、响应时长和满意度。
- 检查产品使用、客服问题与续费之间的相关关系。

### 7.4 DeliveryAgent

- 计算项目延期率、按期验收率和实施周期。
- 对比计划工时、实际工时、定制化程度与毛利。
- 识别影响收入确认和交付成本的项目。

### 7.5 ExternalResearchAgent

- 使用 Tavily 检索低代码、企业软件、数字化服务、行业政策和市场竞争信息。
- 保存标题、URL、摘要和访问时间。
- 把外部信息限定为行业背景或假设佐证，不用于直接证明虚构企业的内部原因。
- Tavily 不可用时使用本地备用行业资料。

### 7.6 EvidenceReviewerAgent

- 复算关键指标并核对口径。
- 检查引用证据是否支持结论。
- 检查是否把相关性错误表述为因果关系。
- 检查跨 Agent 指标冲突和反向证据。
- 接受、拒绝或请求修订 Finding。
- 第二次仍无法解决的问题进入“数据限制与未决问题”。

## 8. 合成企业数据

数据覆盖 2025 年 7 月至 2026 年 6 月。生成程序使用固定随机种子并同时输出 CSV、SQLite、数据字典和仅供评测使用的标准答案。

| 数据集 | 目标规模 |
|---|---:|
| 企业客户 | 240 家 |
| 销售商机 | 约 800 条 |
| 合同及订单 | 约 350 条 |
| 订阅月度记录 | 约 2,500 条 |
| 产品使用月度记录 | 约 3,000 条 |
| 交付项目 | 约 120 个 |
| 客服工单 | 约 1,800 条 |
| 回款记录 | 约 600 条 |
| 内部业务文档 | 10～15 份 |

核心表为 `customers`、`opportunities`、`contracts`、`subscriptions`、`product_usage`、`projects`、`support_tickets` 和 `payments`。客户、合同、订阅、项目和工单通过稳定主外键关联。

内部文档包含公司及产品介绍、定价规则、SLA、验收和收入确认规则、版本发布说明、故障复盘、客户访谈、季度经营计划、输单会议纪要、竞品简报和客服升级制度。

### 8.1 隐藏异常

1. 四个高金额项目延期验收，使约 300 万元收入推迟确认。
2. 高定制项目占比、实际工时和外包成本上升，侵蚀毛利。
3. `CloudFlow v3.2` 的稳定性问题与严重工单上升、功能使用下降及续费下降高度相关。
4. 销售线索数量稳定，但中小客户和华东地区商机赢单率下降。
5. 虚构竞品低价套餐形成竞争压力；真实 Tavily 资料仅提供市场背景。

生成数据的目标趋势为：

| 指标 | 2026 Q1 | 2026 Q2 |
|---|---:|---:|
| 营业收入 | 约 1,870 万元 | 约 1,640 万元 |
| 综合毛利率 | 约 46.8% | 约 38.9% |
| 到期客户续费率 | 约 84.6% | 约 72.8% |
| 项目按期验收率 | 约 86% | 约 64% |
| 商机赢单率 | 约 31% | 约 22% |

精确验收值由固定种子生成结果决定。`ground_truth.json` 位于评测专用目录，不注册到 Agent 工具或知识库，防止答案泄漏。

## 9. 数据访问与工具

统一数据接口为：

```text
BusinessDataProvider
|- list_datasets()
|- describe_schema()
|- execute_readonly_query()
|- get_metric_definition()
`- fetch_evidence_rows()
```

MVP 工具包括：

- `describe_dataset`
- `execute_readonly_sql`
- `calculate_metric`
- `compare_periods`
- `segment_analysis`
- `correlation_analysis`
- `retrieve_internal_document`
- `search_external_information`
- `render_chart`
- `save_report`

SQL 仅允许 `SELECT` 和只读公共表达式，设置最大结果行数和超时，拒绝写入及 DDL 语句。图表只接收结构化数据，报告只能写入指定输出目录。所有工具调用写入审计记录。

## 10. 执行流程

1. 接收并规范用户问题。
2. 用户未提供时间范围时默认最近完整季度，并在结果中注明。
3. Leader 生成结构化 `AnalysisPlan`。
4. 内部分析 Worker 和外部研究 Worker 按依赖关系并行运行。
5. Worker 返回统一 `Finding` 与 `Evidence`。
6. Reviewer 复算并审查所有关键 Finding。
7. 必要时向指定 Worker 发起一次修订。
8. Leader 只综合已接受或明确标记限制的结果。
9. ReportBuilder 输出报告、图表和证据索引。
10. 会话保存计划、查询和证据，以支持范围缩小、解释依据和反事实追问。

## 11. 结构化契约

### 11.1 AnalysisPlan

包含目标、当前和对比时间范围、分析假设，以及最多四个带 `task_id`、目标 Agent、问题、必需数据集和预期输出的任务。

### 11.2 Finding

包含 `finding_id`、标题、事实陈述、可复算指标、证据列表、业务解释、0～1 置信度和限制。指标事实、业务解释和因果判断必须分开。

### 11.3 Evidence

证据编号前缀为：

- `DB`：数据库查询
- `DOC`：企业内部文档
- `WEB`：Tavily 网页
- `CALC`：确定性计算

每个证据保存来源、查询或文档位置、摘要和生成时间。网页证据额外保存 URL 和访问时间。

### 11.4 ReviewResult

包含审查状态、接受和拒绝的 Finding、修订请求、冲突、数据限制和 Reviewer 说明。

## 12. 报告设计

最终报告包含：

1. 执行摘要
2. 核心指标概览
3. 主要异常排名
4. 财务与销售分析
5. 客户、产品与服务分析
6. 项目交付分析
7. 外部行业背景
8. 根因假设与置信度
9. 按优先级、负责人类型和时间范围整理的行动建议
10. 数据限制与待验证问题
11. 证据索引

默认不展示模型内部思考过程，只展示任务计划、工具执行摘要、证据、审查状态和结论。

## 13. 异常处理与降级

| 情况 | 处理 |
|---|---|
| 时间范围缺失 | 使用最近完整季度并明确假设 |
| 问题模糊 | 请求补充；若可安全推断则声明假设后继续 |
| SQL 失败 | 修正一次，仍失败则标记子任务失败 |
| Worker 超时 | 其他任务继续，输出部分报告并说明缺失 |
| Tavily 不可用 | 使用本地资料并标注未完成实时检索 |
| 无支持证据 | 降级为待验证假设，不输出确定性结论 |
| 数据口径冲突 | 展示冲突口径，禁止擅自选择 |
| 模型结构错误 | 结构校验后重试一次 |
| Reviewer 未通过 | 定向返工一次，之后记录限制 |
| 所有关键数据不可用 | 停止经营归因，只输出数据缺口清单 |

## 14. 技术栈

- Python 3.11～3.13；本机使用 Python 3.13。
- AgentScope 2.0.7。
- 阿里云百炼 Qwen 作为默认提供商；启动时必须通过环境变量指定账户可用的模型名称。
- DeepSeek 作为可切换提供商和后续对照评测选项，不作为 MVP 强依赖。
- Tavily API，先通过稳定的 Python 工具适配器接入；MCP 适配器列为第二阶段增强。
- SQLite、Pandas、Matplotlib、Pydantic、Pytest。
- AgentScope Agent Service、现有 Web UI 和 CLI 兜底入口。
- Docker 沙箱为可选增强；MVP 使用只读数据库、工具白名单、超时和指定输出目录保证安全与稳定。

## 16. 测试与评测

### 16.1 测试分层

- 单元测试：数据关系、指标公式、只读 SQL、防写入、结构校验、证据引用和图表生成。
- 集成测试：Agent 调用工具、RAG 检索、Tavily 证据转换、Leader 分派、Reviewer 返工和报告生成。
- 端到端测试：分别以离线和在线模式运行从问题到报告的完整流程。
- 普通测试 Mock 外部 API；少量冒烟测试调用真实百炼和 Tavily API。

### 16.2 评测集

约 15 个问题：3 个综合诊断、3 个财务销售、3 个客户产品、2 个项目交付、2 个客服质量、2 个数据缺失或冲突问题。

评分总分 100：指标准确性 35、异常覆盖率 25、证据完整性 20、稳健性 10、报告质量 10。

MVP 验收目标：

- 核心指标计算准确率 100%。
- 结构化输出校验通过率不低于 95%。
- 黄金案例至少识别 4/5 个关键异常。
- 关键结论证据覆盖率不低于 90%。
- 无证据确定性结论占比不高于 10%。
- 离线降级测试全部通过。
- 综合评测总分不低于 80/100。

结果未达标时如实记录当前分数和已知限制，不只展示最佳一次运行。
