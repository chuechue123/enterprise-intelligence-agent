# BizInsight 知识库页面设计

## 目标

为 BizInsight Web 工作台新增一个独立的只读知识库页面。页面沿用现有应用外壳，并按照参考图展示已进入 RAG 索引的真实内部文档，让用户能够确认 Agent 当前可检索的资料范围。

## 页面与导航

- 页面地址为 `/knowledge`。
- 首页侧边栏中的“知识库 / RAG”跳转到该页面，知识库页面保留同一顶栏和侧边栏，并将该导航项标记为当前页。
- 页面主体采用单列白色资料台：顶部为图标、标题、说明和搜索框，下方为文档表格，底部为计数与分页。
- 桌面端保持参考图的五列结构；窄屏时隐藏次要列并允许标题区域自然换行，不产生横向页面滚动。

## 数据来源与接口

- 新增只读接口 `GET /bizinsight/knowledge/documents`。
- 数据从 `data/knowledge/index.json` 的 `documents` 清单读取，不扫描任意文件系统路径。
- 每个文档返回稳定字段：`document_id`、`title`、`document_type`、`status`、`updated_at`、`source_path`。
- `status` 表示索引状态；出现在索引清单中的文档统一为 `ready`。
- 文档类型由受控规则根据标题、部门和文件名映射为产品文档、制度文档、经营计划、技术文档、客户资料、行业研究或内部资料。
- 接口接受 `query`、`page` 和 `page_size`，服务端完成不区分大小写的名称/类型搜索和稳定分页；`page_size` 限制在 1～50。
- 响应包含 `items`、`total`、`page`、`page_size` 和 `pages`。知识库缺失或内容损坏时返回明确的服务错误，不伪造文档。

## 视觉系统

- 复用现有应用色彩：画布 `#f4f8fd`、表面 `#ffffff`、主文字 `#17233c`、次文字 `#6f7f98`、交互蓝 `#1268f3`、状态绿 `#16a66a`。
- 延续 Segoe UI、Microsoft YaHei UI、PingFang SC 字体栈。
- 文档类型使用低饱和蓝色标签；状态使用绿色圆形勾选和“已就绪”。
- 根据 `.md` 源文件和文档类别显示受控的 Word、PDF、表格或 Markdown 风格文件徽标，不加载第三方图片。
- 交互保持克制：行悬停、搜索框聚焦和分页按钮状态是主要反馈；遵守 `prefers-reduced-motion`。

## 前端行为

- 页面加载后请求第一页文档。
- 搜索输入采用短延迟防抖；关键字改变时回到第一页。
- 上一页、下一页和页码按钮基于接口返回的页数启用或禁用。
- 加载时显示骨架行；空结果提示用户调整关键词；请求失败时说明知识库暂不可用并提供重试按钮。
- 每行操作菜单本期只展示受控的“查看索引信息”，不提供修改、删除、下载或打开任意本地路径的能力。

## 安全与边界

- 页面和接口均为只读。
- 后端不接受客户端提供的文件路径，也不返回绝对路径。
- 操作菜单不把 `source_path` 拼接为可访问 URL。
- 搜索内容只作为内存过滤条件，不进入 SQL、模板或文件系统 API。

## 测试与验收

- 单元测试覆盖文档去重、类型映射、搜索、分页、非法分页参数、索引缺失和损坏。
- Web 测试覆盖 `/knowledge` 页面、侧边栏链接和文档 API。
- JavaScript 行为至少验证搜索、分页、空态和失败态所依赖的 DOM 契约。
- 运行 Ruff、完整离线测试；不要求新增在线模型调用，因为页面只读取本地索引。
- 在桌面和窄屏尺寸进行截图检查，确认布局接近参考图且无溢出。

## 非目标

- 不实现文档上传、删除、编辑、重新索引或权限管理。
- 不新增数据库表或外部存储。
- 不改变现有 RAG 检索和经营分析流程。
